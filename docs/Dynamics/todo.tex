\section{Future Modification and Cleanup}

\subsection{Boundary-Space Lighting}

\subsubsection{Schedule}

The first boundary-space lighting milestone is complete for
\texttt{LightingBall}.  Python proves photon contact and material-source
selection, and Vulkan \texttt{ParticleLighting} now stores persistent
cell-owned visible color in \texttt{BoundaryLightRecord} records.

\subsubsection{Validated Form}

The validated implementation proves:
\[
    \textrm{photon hit}
    \rightarrow
    \textrm{incidence-weighted spectral deposit}
    \rightarrow
    \textrm{persistent cell-owned surface color}
    \rightarrow
    \textrm{analytic surface fragment color}.
\]

This uses cells as the first persistent surface-light owners.  Do not restore
the retired \texttt{BoundaryLightSample}/\texttt{BoundaryLightState} arrays,
visible surface-cell grid, eye-driven brightness, proxy-kernel spread, or
per-frame clear/filter path.

\subsubsection{Next Work}

The next active lighting tasks are:
\begin{enumerate}
    \item diffuse light stream;
    \item absorbing and shadow surface;
    \item reflective surface.
\end{enumerate}

Directional specular, additive energy accumulation, temporal filtering, decay,
and separate compact material response tables remain deferred until these
transport behaviors are stable.

\subsubsection{Diffuse Light Stream}

Create a source mode that emits photons through a controlled distribution of
directions instead of a single x-aligned beam.  The goal is to illuminate the
sphere from a broader field and reduce structured banding that comes from a
single ordered stream.

\subsubsection{Absorbing And Shadow Surface}

Add a material behavior that consumes or blocks photons.  A photon that hits an
absorbing surface should deposit according to the current spectral/incidence
rule and then stop or become inactive.  Surfaces behind the absorber should
remain unlit except for photons that reach them through open paths.

\subsubsection{Reflective Surface}

Add a material behavior that redirects photons after contact.  The reflected
photon should carry the remaining spectral energy so later surfaces can receive
light from the reflection.  This should build on the existing fixed-speed
reflection behavior without making the photon point own the final visible
surface color.

\subsection{Vulkan Test-File View Defaults}

Move the Vulkan initial view defaults that are scene/data specific out of the
application configuration and into the generated \texttt{.tst} file.  In
particular, the current setting:
\begin{verbatim}
initial_view = { rRotZ = 0.0;rRotY=0.0;rRotX=0.0;zoom=0.1;};
\end{verbatim}
should be generated with the test data and read from the \texttt{.tst} file,
not from the Vulkan app configuration file.  This keeps \texttt{view_center},
point size, and initial zoom controlled by the same scene-specific data source.

\subsection{Photon-Direction Specular Lighting}

\subsection{Boundary-Light Washout Cap}

Add an optional render control for LightingBall boundary lighting:
\begin{verbatim}
boundary_light_washout_limit = 0.75;
\end{verbatim}

This would let a lit yellow sector become pale yellow without becoming pure
white.  The center of a dense photon patch could still wash out strongly, but
the final mix toward white would be capped by the configured limit.

\subsubsection{Schedule}

Defer photon-direction specular lighting until the scalar boundary-light path
is proven in both Python and Vulkan:
\[
    \textrm{photon hit}
    \rightarrow
    \textrm{boundary sample energy}
    \rightarrow
    \textrm{filtered lit sector}.
\]

\subsubsection{Target Idea}

Later, boundary light samples may accumulate the incoming photon direction as
well as deposited energy.  A coherent set of photon directions could then
produce a specular highlight from the simulation itself rather than from a
configured analytic light vector.  This should be a second-stage extension,
not part of the first LightingBall memory contract.
